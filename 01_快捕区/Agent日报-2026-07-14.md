## [Bonsai 27B：首款可在手机上运行的 270 亿参数模型](https://prismml.com/news/bonsai-27b) ⭐️ 8.0/10

PrismML 发布了 Bonsai 27B，这是一个 270 亿参数的模型，仅占用 3.9 GB 空间，可在 iPhone 17 Pro 上运行，采用了先进的 1 比特量化（每个权重有效比特数 1.125）和三值表示。 这一突破首次使得 270 亿参数级别的模型能够在手机上本地运行，为隐私敏感和离线 AI 应用提供了高质量文本和多模态能力，可能重塑设备端 AI 的格局。 Bonsai 27B 通过 Qwen3.6-27B 混合注意力架构和 4 比特 KV 缓存量化，支持设备端高达 262K token 的上下文，并且是多模态的，可处理截图、文档和摄像头输入。

hackernews · xenova · 7月14日 17:50 · [社区讨论](https://news.ycombinator.com/item?id=48910545)

**背景**: 大型语言模型通常需要大量内存和计算资源，使其在移动设备上不实用。量化通过使用更少的比特来表示权重来减小模型大小，但极端压缩往往会降低质量。Bonsai 27B 使用三值权重（-1、0、+1）和激进量化，相比 FP16 实现了 14.2 倍的缩减，同时保留了大部分能力。

## [在 GitHub Actions 中缓存友好地使用 uvx](https://simonwillison.net/2026/Jul/14/uvx-github-actions-cache/#atom-everything) ⭐️ 7.0/10

一种在 GitHub Actions 中使用 uvx 的方法，通过设置 UV\_EXCLUDE\_NEWER 环境变量为特定日期，并将该日期纳入缓存键，从而缓存工具下载，并通过更新日期轻松清除缓存。 这种方法通过避免每次运行都从 PyPI 重复下载 Python 工具，显著减少了 CI 工作流的运行时间，对于在流水线中使用多个 uvx 工具的团队尤其有益。 缓存键使用 UV\_EXCLUDE\_NEWER 中的日期，因此更新日期会强制重新下载最新工具版本。该技术记录在一篇 TIL 文章中，并引用了 astral-sh/setup-uv 中一个请求默认启用缓存的现有 issue。

rss · Simon Willison · 7月14日 00:56

**背景**: uvx 是 uv 项目（由 Astral 开发）中的一个工具，用于在隔离环境中运行基于 Python 的命令行工具，无需永久安装。GitHub Actions 工作流通常从头开始运行，因此除非配置缓存，否则每次都必须下载工具。UV\_EXCLUDE\_NEWER 环境变量告诉 uv 忽略在指定日期之后发布的包版本，从而确保可重现性。
